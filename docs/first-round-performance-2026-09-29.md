# 首轮性能优化测量（2026-09-29）

## 环境和方法

- Windows 10.0.26200，Ryzen 9 7940H，32 GB 内存，.NET SDK 10.0.301，Release 构建，SQLite。
- 基线代码为 `6dcbde412676da09aef6a88f8d11da259399f48b` 的独立源码快照；优化后为本分支。两者使用同一份 `FirstRoundBenchmarks` 测试代码。
- 每个用例预热一次，再测五轮。表中耗时是五轮中位数；P95 为五轮样本的最大值，仅用于观察波动，不代表长期负载的可靠分位数。
- SMTP 测试使用内存输入流、76 字节正文行和临时文件输出；同时运行 1 或 8 个连接。分配量来自进程级 `GC.GetTotalAllocatedBytes`，含测试框架噪声。峰值工作集是进程生命周期的峰值，不适合作为单个用例的精确内存差值。
- FETCH 测试使用 1 万或 10 万封邮件的 SQLite 邮箱，软删除中间一封，只以 UID 获取最后一封；SQL 数由 EF 命令拦截器统计。
- 流量统计测试使用一封邮件和一次成功投递，分别测 1 天与 7 天视图；SQL 数由同一方式统计。

重跑命令：

```powershell
dotnet test tests/MailServer.Tests/MailServer.Tests.csproj -c Release --filter FullyQualifiedName~FirstRoundBenchmarks --logger "console;verbosity=detailed"
```

## 结果

| SMTP DATA | 中位耗时：基线 → 优化后 | 样本 P95：基线 → 优化后 | 中位分配量：基线 → 优化后 |
| --- | ---: | ---: | ---: |
| 1 MiB × 1 连接 | 18.5 → 5.7 ms | 20.3 → 6.0 ms | 7.06 → 0.08 MB |
| 10 MiB × 1 连接 | 147.6 → 41.3 ms | 150.5 → 44.7 ms | 69.98 → 0.16 MB |
| 1 MiB × 8 连接 | 39.4 → 15.3 ms | 41.3 → 16.6 ms | 56.48 → 0.67 MB |
| 10 MiB × 8 连接 | 230.6 → 92.1 ms | 247.4 → 224.7 ms | 559.80 → 1.34 MB |

| 查询 | 中位耗时：基线 → 优化后 | 样本 P95：基线 → 优化后 | SQL 读取次数：基线 → 优化后 |
| --- | ---: | ---: | ---: |
| UID FETCH，1 万封，取末封 | 56.4 → 15.4 ms | 65.5 → 16.4 ms | 41 → 3 |
| UID FETCH，10 万封，取末封 | 404.6 → 63.5 ms | 504.1 → 66.8 ms | 392 → 3 |
| 流量统计，1 天 | 175.3 → 21.0 ms | 185.2 → 34.9 ms | 26 → 4 |
| 流量统计，7 天 | 165.6 → 19.9 ms | 553.3 → 22.7 ms | 30 → 4 |

10 MiB 单连接的中位分配量下降约 99.8%，超过原定 50% 目标；但这是上述内存流与本机文件写入场景的结果。8 连接的 SMTP P95 波动仍明显，部署环境需继续观察。

## 正确性和限制

- 协议测试覆盖跨块 CRLF、点转义、截断、大小限制、读取超时、命令与 literal 共用缓冲，以及 STARTTLS 时清除明文缓存。现有协议测试还覆盖实际 SMTP/IMAP 命令路径。
- FETCH 回归测试覆盖稀疏 UID、倒序和重叠范围、空结果及软删除后的真实序号。普通序号 FETCH 仍需扫描到请求的最大序号，只减少了非命中邮件的详细数据加载。
- SQLite 的流量统计覆盖空数据、成功和两类失败及精确 P95；仪表盘保持原有结果口径。
- 本次 SMTP 基准没有经过真实网络或 TLS；正式上线前应对收信吞吐、P95、GC 分配、数据库查询量、协议错误和内存峰值持续观测。
- MySQL 验收测试已加入 UID 缺口、流量统计和仪表盘场景。`MAILSERVER_TEST_MYSQL_CONNECTION` 未配置，且本机无 Docker；这些场景的实际 MySQL 执行尚未验证。发布前须在独立 MySQL 验收库运行该测试。
