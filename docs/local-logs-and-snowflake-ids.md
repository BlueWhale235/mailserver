# 本机日志与雪花 ID

此版本面向**全新业务数据库**。实体主键和外键使用 `long`，MySQL 存为 `BIGINT`，SQLite 存为 `INTEGER`。GUID 版本数据库不能直接升级；保留原库，另建空库，再运行 `mailserver db update` 或 `mailserver init`。本次没有提供旧数据 ID 转换工具。

## 日志存储

审计日志、性能明细与汇总、任务执行历史、投递尝试记录写入本机独立 SQLite。业务库中不再创建这些日志表。控制台和可选文本文件日志继续由原有日志配置控制。

```json
{
  "LocalLogs": {
    "Path": "data/logs.db",
    "RetentionDays": 30
  },
  "Snowflake": {
    "MachineId": 0,
    "StateDirectory": "data/snowflake"
  }
}
```

“全局设置 → 本机日志”可修改当前机器的保留天数，范围 1～3650 天，默认 30 天。修改保存在本机日志库中；未修改时采用配置文件。后台在启动时及每 5 分钟分批清理，严格删除时间早于截止时间的记录。任务执行历史按完成时间计算，未完成历史按开始时间计算。性能采集原有明细/汇总保留期限和明细空间上限仍可提前清理性能记录。

SQLite 使用 WAL，生产日志连接设置 `synchronous=NORMAL` 和5秒忙等待。已提交业务产生的新增审计、投递尝试记录通过容量4096的有界队列聚合，每批最多256条、低流量等待5毫秒。调用方等待批量写入结果以保留 API 的写后读可见性；业务提交后的日志失败仍只记录告警。日志库路径必须与 SQLite 业务库不同。API、SMTP、IMAP、Worker 若在同一机器上独立运行，应指向同一个本地日志文件；容器部署需要共同挂载本机日志目录。不同机器各自保存日志，管理页面只显示当前机器能访问的日志，不自动汇总其他机器记录。禁止多台机器通过网络文件系统共同写同一个 SQLite 文件。

日志保留业务关联 ID，不建立跨库外键。任务记录额外保留当时的任务名称和类型。域名审计先从业务库取得相关资源，再查询本机日志；投递任务的状态、租约、次数和重试幂等状态始终属于业务库。

业务与日志不构成分布式事务。审计/任务/投递日志在业务提交成功后写入本地库，业务回滚时丢弃待写日志。日志写入失败会记录告警、增加本进程失败计数，但不会把已经完成的业务操作报告为失败。业务提交后进程突然退出可能丢失尚未写入的日志；此实现不提供零丢失审计保证。性能采集仍使用有界队列和独立批量写入。

## 多机编号

ID 使用 2020-01-01 UTC 为纪元，分为 41 位毫秒时间、10 位生成节点、12 位序号。`MachineId` 范围为 0～127，必须在所有需要合并数据的机器/部署实例间唯一。默认 0 仅适合单机。

节点编号为 `MachineId * 8 + ProcessSlot`。进程槽位默认如下：

| 进程 | 默认槽位 |
| --- | --- |
| API | 0 |
| SMTP | 1 |
| IMAP | 2 |
| Worker | 3 |
| CLI | 4 |
| 单进程 RunAll | 5 |

同一机器同一角色运行多个副本时，显式设置不同的 `Snowflake:ProcessSlot`（0～7）；槽位必须在该机器所有生成进程间唯一。例如默认 Worker 使用 3，第二个 Worker 可以使用 6。不要复用已被 API/CLI 等占用的槽位。不要通过 PID 或随机编号分配生成节点。

生成器持有节点状态文件的独占锁，预留10秒时间窗，剩余30%时异步刷新持久化边界。只有已经落盘的窗口可用于返回 ID；冷启动或窗口耗尽仍等待落盘，但不在 ID 分配锁内执行磁盘刷新。正常重启从预留时间段之后继续生成，可能产生约10秒逻辑时间偏移；连续快速重启可能因持久化边界过于超前而拒绝启动，需要等待真实时钟追上。运行期间超过5秒的实际时钟回退仍拒绝生成。节点状态目录必须持久化，不能在可能回退时钟的情况下删除或回滚状态文件；同一节点编号跨机器重复配置无法由本地文件锁检测，部署时必须保证编号唯一。

HTTP API 和审计导出中的 ID 使用十进制**字符串**，防止 JavaScript 丢失 64 位整数精度。请求接受十进制 ID 字符串，路由使用十进制整数。配额、字节数、次数等普通数字保持原有 JSON 数字格式。插件 SDK 的实体 ID 参数也已改为 `long`，依赖旧 GUID 签名的插件需要重新编译。

本次验证覆盖生成器、SQLite、HTTP API 和管理页面；不能据此断言多机实际吞吐提升，也不能仅凭 MySQL 模型与迁移 SQL 验证断言线上 MySQL 已运行成功。
