# 性能分析：实现与验收记录

## 使用

在后台“运维中心 → 性能分析”查看慢操作、耗时排名和采集状态。全局 `performance.read` 可查看，`performance.manage` 可修改采样、阈值、保留期及启动 15 分钟全量详情诊断。诊断模式到期自动失效，也可手动停止。设置存于 `system_settings`，各进程约 10 秒内读取；所有设置变更写入审计。

默认开启计时，正常操作采样 1% 的阶段详情；慢操作和错误保留详情。慢阈值为 HTTP/IMAP 500 ms、SMTP 1000 ms、投递 3000 ms；阶段 200 ms、单条 SQL 200 ms、累计 SQL 500 ms、同指纹重复 20 次。详情保留 7 天、聚合保留 30 天，详情逻辑预算 512 MiB。每次操作最多 256 个阶段、64 KiB 详情，进程缓冲默认 8 MiB，512 MiB 资源档位使用 2 MiB。容量耗尽或数据库故障时丢弃诊断记录，采集状态展示计数和故障，不让诊断写入阻塞邮件路径。独立进程每分钟各写自己的聚合；存储与查询自身不进入采集。启用后需先对 SQLite 或 MySQL 执行对应数据库迁移。

按 `TraceId`、邮件 ID 或投递任务 ID 可以找相关操作。入库的邮件与投递任务保存来源追踪 ID，Worker 的每次重试是单独操作。详情显示总耗时、处理耗时、等待、SQL 执行与读取生命周期、排队和退避。阶段总耗时包含子阶段，自身耗时扣除直接子阶段的时间并集；并行阶段不应相加。未细分耗时包含尚未加埋点的代码。排队时间由领取时刻与计划执行时刻计算，重试退避由上次更新时间与计划执行时刻计算；发现负值时归零并标记时钟异常。连接与事务事件采用 EF Core 报告的耗时回填；数据库命令计数与执行耗时独立统计。P50/P95/P99 由对数时间桶估算，实际单次操作耗时和阶段耗时仍按单调时钟测量。

SQL 指纹保留结构化模板，不保存参数值、原始 SQL、邮件正文、认证信息或异常消息。单引号字面量统一替换为 `?`，双引号标识符只在与 EF 模型列名或表名一致时保留，无法安全解析的模板统一显示为不可用。详情只保存异常类型。后台以全局权限限制访问，页面提供采集丢弃、截断、存储故障提示。API 路径是 `/api/v1/operations/performance`，支持时间、模块、状态、追踪 ID、邮件 ID、任务 ID、最小处理耗时及慢操作筛选，游标分页每页 50 条。排名最多读取 20,000 条分钟聚合，超限会明确提示缩小时间范围。

## 本机验证

环境：Windows 11 专业版，AMD Ryzen 9 7940H，约 31.2 GiB RAM，.NET SDK 10.0.301 / runtime 10.0.9，SQLite，Release。SQLite 迁移、采集器、SQL 脱敏、同步与异步命令、阶段重叠、容量限制、存储故障、HTTP 权限与分页均由自动化用例覆盖。后端回归 384 项通过，前端 203 项通过，前端构建与 lint 通过。隔离的本地 HTTP 实例中实际登录后台并确认性能分析页加载和操作列表渲染。MySQL 迁移已生成，专用验收数据库的采集与事务用例已加入；当前机器没有 `MAILSERVER_TEST_MYSQL_CONNECTION`，**MySQL 实库未验证**。

显式基准使用同一台机器、同一 Release 构建、预热 1 轮、记录 5 轮中位数与 P95。下表仅是微基准，计时结果不写入单元测试断言。

| 用例 | 关闭采集 | 开启采集 | 解释 |
|---|---:|---:|---|
| 10,000 个操作，每个 5 阶段，中位数 | 0.17 ms | 106.86 ms | 约 10.7 µs/操作的纯采集成本；关闭组无实际业务工作，百分比不代表生产开销 |
| 同上 P95 | 0.27 ms | 112.21 ms | 5 轮样本的第 5 值 |
| 同上分配量中位数 | 30,440 B | 99,088,360 B | 约 9.9 KiB/操作；包括 Activity、阶段对象及聚合 |
| 10 MiB SMTP DATA × 8 并发，中位数 | 69.34 ms | 53.70 ms | 输入为内存流和本机临时文件；差异受 I/O 缓存、调度影响，不能解释为采集提高吞吐 |
| 同上 P95 | 70.48 ms | 55.34 ms | 5 轮样本的第 5 值 |
| 同上分配量中位数 | 1,316,952 B | 1,329,624 B | 增加约 0.96% |
| 峰值工作集 | 126,603,264 B | 127,279,104 B | 该进程生命周期内的峰值，非逐轮独立测量 |

命令：`$env:MAILSERVER_PERFORMANCE_BENCHMARK='1'; dotnet test tests/MailServer.Tests/MailServer.Tests.csproj -c Release --filter 'FullyQualifiedName~CollectorBenchmark|FullyQualifiedName~ProtocolTelemetryBenchmark' --logger 'console;verbosity=normal'`。真实 SMTP/IMAP 网络、TLS、MySQL 与完整收投流程的端到端 5% 开销目标仍需在验收环境压测，当前微基准不足以证明达标。发布后观察每分钟聚合、缓冲丢弃、数据库写入延迟、错误率以及收信与 FETCH P95；若采集故障或显著回退，可通过性能设置关闭采集。
