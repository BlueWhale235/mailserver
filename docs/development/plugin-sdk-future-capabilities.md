# Plugin SDK 后续能力规划

[返回文档索引](../README.md)

当前第一批已落地的宿主能力包括：插件发信、投递队列控制、目录查询、邮件读取/编辑、审计写入与插件状态存储。下面是后续建议继续扩展的能力池。

## 建议后续增加的能力

- 隔离区能力：支持插件将可疑邮件放入隔离区、释放、删除、查询隔离记录，并和后台审核页面联动。
- 邮箱操作能力：支持移动邮件、复制邮件、设置 flags、创建邮箱文件夹、标记已读/未读，供反垃圾、自动归档和规则插件使用。
- 限流与信誉能力：支持按 IP、账号、域名、收件域进行速率限制、临时封禁和信誉评分。
- DNS 与网络辅助能力：提供受控 DNS 查询、HTTP client、统一超时、代理和证书策略，供 SPF/DMARC/RBL/OIDC/Webhook 插件使用。
- 认证增强能力：提供外部身份映射、token 缓存、OAuth/OIDC discovery 辅助、认证事件追踪和多因素状态扩展。
- Webhook 与事件订阅：支持邮件接收、投递结果、登录成功/失败、域名变更、账号变更、插件配置变更等事件订阅。
- 插件指标能力：记录每个插件执行次数、拒绝/延迟/隔离数量、错误数、平均耗时和最近错误，后台插件页展示健康状态。
- 插件密钥能力：为 API key、OAuth client secret、Webhook secret 提供加密存储、轮换和脱敏展示。
- 管理类能力：在明确权限模型后，允许特定系统插件创建/更新账号、别名、规则、域名配置。
- 投递策略扩展：允许插件在 Direct MX 投递前执行合规检查、暂停或拒绝，并记录可审计的判定原因。

## 设计原则

- 插件不直接访问数据库实体，通过受控 service facade 调用宿主能力。
- 策略型能力必须可审计，涉及邮件状态变化时必须留下插件动作记录。
- 可变更邮件内容的能力只在明确阶段开放，避免已展示或已投递内容被无痕修改。
- 网络、DNS、密钥、状态等跨插件资源统一由宿主管理，避免每个插件自己实现一套不一致的安全策略。
- 默认保持最小权限；未来如果增加第三方插件权限声明，应在 manifest 中显式声明能力需求。
