# 同一邮箱 UID 与配额并发测试（2026-09-29）

本轮只验证现有实现，没有修改 UID 分配或配额更新逻辑。新增 SQLite 文件数据库测试：八个独立请求同时向同一邮箱投递，账号与域名配额均仅允许三封邮件。测试断言已接受邮件的 UID 从 1 连续递增、`UidNext` 正确、账号及域名 `UsedBytes` 等于实际接收字节数，且邮件和配额流水条数与成功数一致。配额超限或数据库竞争失败均不得被误报为成功。

新增用例连续运行五轮均通过；整组配额及 SMTP 失败处理测试 30 项通过。SQLite 的竞争失败仍可能返回临时错误，这项测试验证一致性，不表示八路请求都能成功，也不能证明吞吐有所改善。现有 SMTP 收信使用可串行化事务，UID、账号配额及域名配额在同一事务内更新；同邮箱并发仍会争用这些记录。

当前未设置 `MAILSERVER_TEST_MYSQL_CONNECTION`，也未提供独立的 `mailserver_acceptance` 验收库，因此本次 **MySQL 实库未验证**。线上或测试服务器先前的成功投递记录不能替代专项验收。下一步如要优化锁竞争，应先在独立 MySQL 库测试同邮箱和不同邮箱并发，记录死锁、重试、P95、UID 与配额结果，再比较改动前后。
