## 1. 先读：当前已经完成，不要重复修改

- 登录页已经确认完成，除非发现明确功能缺陷，不再重做视觉设计。
- 技术栈固定为 Vue 3 + TypeScript + Vite + Vuetify + API，不使用 Razor／Blazor。
- 仅支持 Direct MX，不恢复 Relay。`Relay` 配置节点继续由 CLI 明确拒绝启动。
- 防火墙已经采用“单行备注 + 多行 IP/CIDR，一行一个”；删除只需直接确认，不要求重复输入名称。
- 弹窗操作按钮统一右对齐。
- 域创建、域列表请求竞态、新域 Mock 健康数据、Direct MX 首次检查已修正。
- 邮箱和别名单页分页、搜索清空、请求乱序保护已经存在；不要继续按旧 To-do 描述重做。
- 邮箱单条／批量软删除已经有确认、运行中账号阻断、回收站说明和失败重试。
- DNS、证书、域配额、域基础配置已经有未保存保护；域基础配置点击取消也需要二次确认。
- 隔离邮件页面预览已限制为 256K 字符，并提供完整 `.eml` 下载。
- 当前前端基线：13 个测试文件、136 项测试通过；ESLint、TypeScript 和生产构建通过。
- 当前后端基线：232 项测试通过。除升级说明外没有 Relay 产品模式实现。
- 不擅自部署、删除数据库、操作生产数据或额外制作发布压缩包。

### 2.2 后端接口虽然存在，但仍不等于生产就绪

- 管理后台当前调用的域、投递、隔离、系统设置、管理员、API Key、任务、审计和插件接口大多已经注册。
- 浏览器 Cookie、CSRF、JWT、API Key 和会话接口已经存在。
- SQLite、PostgreSQL、MySQL 都已经有新的 `InitialMailServer2` migration；启动会拒绝旧 migration 链。
- DeliveryAttempt 已有阶段、远端地址、状态码、TLS、耗时、失败分类、重试时间和会话摘要字段；维护任务会清理 30 天前记录。
- Direct MX 已包含 MX／A／AAAA、MTA-STS、DANE、TLS-RPT、故障转移和退避相关实现，后续应补验证而不是重新设计另一套传输。

仍未完成的生产要求：

- `/api/v1/health/ready` 当前无条件返回 `ready`，不能代表数据库、迁移、消息存储或安全目录真的可用。
- `/api/v1/health` 只检查数据库并且匿名开放，没有授权后的 SMTP／IMAP／Worker／存储／证书详细健康快照。
- 后端没有 OpenTelemetry 包和 OTLP exporter 配置。
- `Program.cs` 仍有约 42 处 `Results.BadRequest(new { error = ... })`，尚未统一为 RFC Problem Details／字段级验证错误／traceId。
- 前端 DTO 仍由页面手写；没有从 OpenAPI 生成 TypeScript 类型或客户端。
- 系统设置 UI 宣称包含 SMTP、IMAP、存储和可观测性，但实际只提供投递、SMTP 命令超时、默认文件夹和证书选择四组设置。
- IMAP 命令超时仍只读取启动配置；SMTP 命令超时和投递设置已支持数据库动态读取，两者运行语义不一致。
- 路由没有页面级权限 meta；目前主要依靠侧栏／功能入口隐藏和后端鉴权，直达 URL 的前端体验不完整。
- `.gitea/workflows/release.yml` 只执行发布打包，没有运行前端测试、lint、`.NET test` 或三数据库集成验证。
- `package.json` 的 Vue、Vuetify、Vite、TypeScript 等依赖仍全部使用 `latest`。

## 6. 建议分配给其他模型的方式

为减少共享工作区冲突，建议按下面边界分配，不要让多个模型同时改 `Program.cs` 或 `DomainDetailView.vue`：

1. 后端模型 A：`BE-01`、`BE-02`、`BE-03`，负责健康、可观测性和概览聚合。
2. 后端模型 B：`BE-04`，负责运行时设置契约与 SMTP／IMAP／Worker 生效语义。
3. 后端模型 C：`BE-05`、`BE-06`、`BE-16`，负责分页、RBAC、Problem Details 和 OpenAPI 生成。
4. 后端模型 D：`BE-07`、`BE-08`、`BE-10`，负责投递与隔离并发安全。
5. 后端模型 E：`BE-09`、`BE-11`、`BE-12`、`BE-13`、`BE-14`，负责系统管理服务。
6. 前端模型 A：概览、全局设置、消息模板。
7. 前端模型 B：管理员、API Key、路由权限。
8. 前端模型 C：投递中心、隔离共享组件。
9. 当前线程继续负责浏览器逐按钮验收、交互一致性和合并后的回归修复。

每个模型交付时必须写清：

- 改了哪些文件和接口；
- 是否连接真实数据库／真实 HTTP API；
- 自动化测试数量和命令；
- 哪些按钮实际在浏览器点过；
- 仍未覆盖的风险；
- 不得用 Mock 测试通过代替生产 API 验收。
